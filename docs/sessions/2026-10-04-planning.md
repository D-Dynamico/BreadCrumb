# 2026-10-04: Planning

## Scope

Turn the "Autonomous AI Task Worker" brief into a plan and a documentation set that
Claude Code can build from. No code written in this session.

## What was decided, and why

1. **First plan: verification-first ("Attest").** Contract-first execution, a verifier
   on a separate read path with provenance, and a chaos harness measuring
   false-completion rate.
2. **Independent review of that plan** (a separate agent acting as a hiring panel).
   Main points: about two weeks of scope squeezed into seven days; the verifier only
   confirms whatever the contract says, so the contract needs typed checks; zero false
   completions on a self-built sandbox looks rigged without a separate oracle and
   held-out tasks; "separate channel" overstated, since the verifier reads the same
   data; suggested a verifier ablation as the single strongest addition. Suggested cuts:
   run replay, vision cross-check, cheaper-model split, team chat as an app, extra
   traps.
3. **Concern raised: the approach leaned too much on earlier projects** (deterministic
   verifier over LLM output, fact validation, finance domain). Agreed.
4. **Three directions weighed**: verification-first, crash-safe resumable worker,
   procedure memory. Scored against the brief's eight criteria plus overlap with past
   work, schedule risk, demo strength and rarity. Crash-safe resume won (see
   `DECISIONS.md` D1). Verification kept as a lean built-in, since resume needs it
   anyway to find out what actually happened. Procedure memory became "what's next".
5. **Sandbox made generic**: Acme Co. with payables, people and tickets, not an
   accounts-payable-only world, so task families genuinely differ.
6. **Name: Breadcrumb.** It drops a breadcrumb before and after every action, so it can
   always find its way back. Tagline: "an AI worker that can be interrupted and still
   finish the job."
