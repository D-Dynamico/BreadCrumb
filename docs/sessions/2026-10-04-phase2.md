# 2026-10-04: Phase 2, the bare agent on the happy path

Follows `2026-10-04-phase1.md` in the same working session.

## Scope

Model client, generic tools, executor loop with a plan and a simple `finish`. Exit:
family 1 happy path completes 3 out of 3 runs against the real sandbox, with a
readable step log. No journal, gateway, contract or verifier yet (Phases 3 and 4).

## Changes

- **Model client** (`breadcrumb/llm/client.py`, D27). Checked Google's docs first: the
  Interactions API is now the recommended interface, usable statelessly with
  `store=False`. One call per turn with `tool_choice: any` and `thinking_level: low`;
  verified with one real call before building on it (`google-genai` 2.28.0). Paces
  itself under 15 requests a minute, retries 429, 5xx and dropped connections with
  backoff, dev cache keyed by the exact request, per-day request count in
  `runs/llm_usage.json`.
- **Browser tool** (`breadcrumb/tools/browser.py`, D29). Playwright ARIA snapshot with
  numbered interactive elements, compacted (row names, cell wrappers, URLs and echoed
  labels dropped). Elements resolved by role, name and position. Downloads captured
  into the run folder. `login()` matches the app by URL and fills credentials from
  config. Network watch: every non-GET request is checked against the declared action
  (`submit` or `login`); anything else is logged as an integrity violation and
  reported to the model.
- **Files, HTTP and notify tools.** PDF text with `p1 L5:` locators; a file with no
  text layer is reported as unreadable with "do not guess". The HTTP tool reads the
  OpenAPI spec and lists one line per operation; writes carry `Idempotency-Key`. Notify
  posts to the requester's channel with the run's `Ref: BC-XXXX` token.
- **Executor** (`breadcrumb/executor/`). Structured state (plan, facts with source and
  step, history, latest observation) rebuilt into one prompt per turn, observation
  fenced as untrusted data, last 10 actions shown. Budgets for steps, wall time and
  tokens end a run as `failed` with the reason. Step log in
  `runs/<run_id>/steps.jsonl`, summary in `summary.json`, live log on the console.
- **Prompt** (`prompts/executor.txt`). Generic working rules. Two wording fixes before
  the first run: an example locator said "invoice", and "never change payment details"
  described a trap; both removed (ground rule 4: defences are structural).
- **CLI** `breadcrumb run "<task>" [--headed] [--no-cache] [--max-steps N]`; stdout set to
  UTF-8 so ₹ prints on Windows.
- **Harness helpers**, pulled forward from Phase 6 because this phase's exit needs an
  honest judge: `harness/scoring.py` (records, unchanged and messages checks against
  the oracle) and `uv run tasks render --task` / `uv run tasks score --task`.
- **First dev task**: `harness/tasks/dev/dev-invoice-happy.yaml` (the brief's example).
- **Docs**: `AGENT_DESIGN.md` (action space as built, tools, context), `ARCHITECTURE.md`,
  `.env.example` (`LLM_THINKING_LEVEL`, `LLM_REQUESTS_PER_MINUTE`, `API_BASE_URL`,
  `NOTIFY_URL`, `NOTIFY_CHANNEL`, `HEADLESS`), `CLAUDE.md` commands and status,
  `DECISIONS.md` D27 to D30.

## What the runs taught us

1. **Mypy caught a crash before any run**: two actions had a parameter called
   `description` or `name`, which collided with the schema helper's own arguments.
2. **Run A (failed, 9 steps)**: a dropped connection from Google ("Server disconnected",
   no status code) was not retried; and the model spent 4 of 9 turns on plan updates.
   Fixed: dropped connections retry; `plan` and `remember` became fields on every
   action (D28).
3. **Run B (finished, but wrong; would have scored FAIL)**: never opened the inbox. It
   took the vendor's older invoice already in Admin as "the latest" and declared the
   job done. Nothing was written. Cause: the worker did not know what each system is
   for. Fixed with one-line system purposes in config and two generic rules (D30).
   This is the false completion the Phase 4 verifier is meant to catch; keep it as a
   test case for the verifier ablation.
4. Also seen: the model typed an amount into a date field (Playwright refused, the
   error went back to the model), re-sent its whole fact list each turn (prompt now
   says only new facts), and sometimes revisits pages it has seen.
