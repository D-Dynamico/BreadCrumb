# 2026-10-04: Phase 1, the sandbox

Follows `2026-10-04-phase0.md` in the same working session.

## Scope

Build Acme Co.: Mailbox, SupplierHub vendor portal, Acme Admin with its partial API,
seeded data with PDFs and the five traps, the oracle, the launcher, and the frozen
held-out tasks. No agent code.

## Changes

- **Shared plumbing** (`sandbox/common/`). Config with `.env` fallback and per-call
  paths (so tests can point at a temp copy), SQLite in WAL mode, an append-only
  `audit_log` (triggers refuse UPDATE and DELETE), money in paise with Indian grouping,
  and a small web kit: server-side sessions, one cookie name per app (browsers share
  cookies across ports), CSRF tokens, an HTML error page, login and logout routes.
- **Fault hook** (`sandbox/faults/`). Every app runs behind it. Only `none` exists; any
  other profile refuses to start ("arrives in Phase 4") rather than running clean.
- **Seed** (`sandbox/seed/`). `build_scenario(seed, today)` is pure and builds the whole
  world as data; `write_world` turns it into the database, PDFs and `scenario.json`.
  12 vendors (ten roles plus a look-alike pair), 30 invoices, 15 emails, 2 new hires,
  two backfill batches (one invoice listed twice in each), five traps. Recent invoices
  are due at least 10 to 25 days out, so tasks are always possible on the seed day. The
  first version used exactly 10 days, which made many due dates identical on the portal;
  spotted in a screenshot and varied.
- **Acme Admin** (`sandbox/apps/admin/`). Business rules in `records.py`, shared by the
  web routes and the API. Payables (validation, no duplicate check per D17, above
  ₹1,00,000 goes to `pending_approval`, only the approver role may approve), vendors
  (bank details editable, audited), purchase orders, people, tickets, team messages.
  API at `/api` with OpenAPI spec and operation ids; `Idempotency-Key` on writes
  replays the first response, and a reused key with a different body gets 409 (D19).
- **Mailbox and SupplierHub.** Inbox and sent with search, PDF attachments, compose:
  `@acme.test` delivers internally, anything else lands in `outbound_mail`, unknown
  Acme mailboxes are refused. SupplierHub lists Acme's invoices with PDF downloads.
- **Oracle** (`sandbox/oracle/`). Read-only, localhost, `/records/<source>` with exact
  filters and `after_id`, `/scenario`. Logins and sessions are never exposed.
- **Launcher** (`uv run tasks sandbox`) starts the four services as separate processes
  on 127.0.0.1. `uv run tasks seed --seed N [--today YYYY-MM-DD]` works.
- **Task files** (`harness/taskfile.py`, D24). Jinja templates over the scenario,
  strict rendering, Pydantic schema for ground truth (`records`, `unchanged`,
  `messages`).
- **Held-out tasks** (`harness/tasks/heldout/`, five files): look-alike vendor, large
  invoice needing approval, onboarding the second new hire, backfill of the second
  batch with a `mid_batch:2` crash, and the bank-detail change email. Frozen by
  `FROZEN.sha256` (line endings normalised) and a test that fails if any file changes.
- **Generality check.** Reads nested pools, denies each name's first word too, and
  reads task ids with a pattern because task files are templates. 158 names denied.
- **Libraries** (D25): reportlab, pdfplumber, Pillow, types-reportlab; htmx 2.0.11
  vendored into `sandbox/static/`.
- **Docs**: `SANDBOX.md` (People module, SupplierHub, roles, seed date rule, oracle
  endpoints, realism details), `ARCHITECTURE.md` (layout), `EVALUATION.md` (task file
  format), `AGENT_DESIGN.md` (deny-list), `.env.example` (sandbox-only keys),
  `DECISIONS.md` D24 to D26, `CLAUDE.md` status.

## Verification

- `uv run tasks lint`: exit 0 (ruff, format, mypy strict on 53 files, generality
  check with 158 denied names).
- `uv run tasks test`: exit 0, 46 passed. Highlights: same seed gives the same world;
  every seed's amounts and due dates make every task possible; text PDFs extract and
  the scanned one yields nothing; audit log refuses edits; crawling every GET page
  writes no audit rows; validation messages; the same invoice can be entered twice;
  approval rules; field-level audit of a bank change; CSRF; API auth, no payable
  creation over the API, idempotent replay and 409; outbound mail; oracle read-only and
  never exposing logins; every task file renders under seeds 1, 2, 3 and 42; held-out
  files unchanged.
- **Exit criterion 1, a human can do families 1 and 2 in a browser.** Scripted
  walkthroughs in `tests/sandbox/test_walkthroughs.py` read values off the pages and
  PDFs (never the scenario) and pass. Then, against the real running sandbox (seed 1)

    PDF, entered it in Admin, posted on #finance-ops. Saved as `PAY-1014`; oracle shows
    exactly one payable, amount `18927.20` as expected, status `entered`. The browser
    sent only five non-GET requests: three logins, the payable form and the message.
  - Family 2: opened the offer letter, added the employee, raised an IT ticket through
    the web form, emailed the personal address. Oracle record matches the answer key on
    every field, one new IT ticket, one outbound email to the right address.
  - Screenshots checked by eye: inbox, saved payable, SupplierHub list, and the
    scanned invoice (readable by a person, no text layer).
- **Exit criterion 2, oracle ground truth.** Confirmed in both walkthroughs above and
